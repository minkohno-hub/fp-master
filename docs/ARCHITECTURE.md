# アーキテクチャ

React + TypeScript + Viteによる静的PWA。GitHub Pagesを基本の公開先とし、バックエンドやアカウントを前提としない。クラウド同期は未提供。各モジュールの実装状況は `TASKS.md` を参照する。

## 境界

| 層 | 責務 | 依存上の原則 |
| --- | --- | --- |
| UI | 日本語ナビ、条件設定、1問演習、解説、データ管理、状態通知 | IndexedDBを直接操作しない |
| curriculum/catalog | 教材スキーマ、検証・公開ゲート、論点、公式仕様メタデータ | 未確認を本番カタログへ混入しない |
| assessment | 条件抽出、必要数/不足、重複防止、選択/数値採点 | 通常から計算除外、模試は独立条件 |
| calculation | 明示的な単位・精度・端数処理、生成問題の正答導出 | 浮動小数の暗黙比較に依存しない |
| review | 自己評価に応じたSM-2型の予定算出 | 現在時刻を引数化して再現性を確保 |
| analytics | 初見/復習/期間/分野/難度/模試、網羅・習得の別評価 | 未学習と不正解、0件と0%を区別 |
| storage | IndexedDB、更新、移行、JSON出入、検証、原子性 | 成功はtransaction完了後、失敗は破壊しない |
| PWA | manifest、app shell cache、更新通知 | 学習データをキャッシュ削除対象にしない |

## データの状態遷移

教材は「未確認」→「原典照合済み」→「公開可能条件の確認」→「本番出題対象」とする。原典照合と公開権利は別属性。廃止・改正影響・根拠切れは出題対象から除外し、履歴の参照IDは維持する。構造検証は内容検証とは別のゲートとする。

学習者の回答には問題ID、学習モード、初見/復習の区別、解答時間、自己評価、正誤と日時を記録する。問題IDは再利用しない。内容変更による採点影響はデータバージョンと変更理由で追跡する。

## 保全と復元

学習データはIndexedDBのバージョン付きドキュメントで保存する。旧localStorageの `fp-master.history.v1` を確認し、非破壊で移行する。バックアップは形式・版・必須値・レコードID・参照を検証した後、一つの更新としてコミットする。失敗は既存データを維持する。自動的に壊れたデータを消去しない。

## UXと拡張

モバイルは下部ナビ、短時間演習、十分な文字・タップ領域。PCはサイドバーと適切な文章幅を持ち、キーボードで主要操作に到達できる設計にする。light/darkは共通トークンを用いる。教材がない場合も不足理由・出典確認状況・安全な設定/バックアップへの導線を提供する。

用語/カード/計画/模試は独立したデータ・状態として追加し、採点や履歴のロジックを画面へ複製しない。教材の大量化では分野/級によるチャンク読込と索引を検討する。GitHub Pagesの `/fp-master/` 配下のパスとオフラインキャッシュ範囲を整合させる。
