# 設計判断

## ADR-001: React / TypeScript / Viteを継続

既存基盤を活用し、ブラウザ内で完結する静的配信を維持する。GitHub Pagesでサーバー秘密鍵を保持する設計を採用しない。CSSは既存を生かし、Tailwindを導入すること自体を目的にしない。

## ADR-002: 確認済み教材と構造の正しさを分離

スキーマを満たすだけでは試験知識が正しいとは判断できない。原典照合・最終確認日・利用条件を別々に持ち、いずれか不足する問題は本番出題しない。公式未取得の現在は教材0件を正直に示し、デモを完成品に混在させない。

## ADR-003: IndexedDBと原子的復元

履歴・再開状態・設定が増えるため、localStorageの全文同期書込からIndexedDBへ移行する。旧データは削除しない。復元は検証後の原子更新とし、不正JSON・非対応版・競合ID等で既存データを変化させない。クラウド同期は認証・競合・バックエンドが別途必要なため未提供。

## ADR-004: SM-2型の間隔反復

FSRSより少ない学習履歴・パラメータで説明可能な初期方式としてSM-2型の自己評価ベース予定を採用する。正答でも曖昧なら短い間隔で復習する。採用した具体式・境界はコードとテストを正とし、学習効果や95%達成を保証しない。後に履歴が十分蓄積した場合にFSRS等を評価する。

## ADR-005: 網羅率の分母を推測しない

公式全論点の取得・版確定前は、6分野の存在や問題数から完全網羅率を算出しない。教材件数、仮分類の充足、公式網羅率、本人習得率を分ける。仮分類の進捗を公式試験範囲の数値に見せない。

## ADR-006: 通常と模試の出題方針を独立

通常演習は初期設定から計算を除外する。計算専用は計算のみ。模試は通常の除外条件に依存せず、公式確認済みの配分に従う。必要数不足は開始可能数・不足数を返し、重複で埋めない。

## ADR-007: PWA更新と公開を手動にする

オフラインのapp shellと学習DBを分離し、更新時に未保存回答を自動再読込しない。GitHub Pagesは手動ワークフローを基本とし、許諾不明教材を自動公開しない。ビルド成功と実デプロイ成功を区別する。
